# 候选模型与评测设计

资料核对日期：2026-11-10。本项目通过百炼直连、API易、BananaRouter 和 RunningHub 调用模型；第三方渠道的实际账单价格必须按各自账户核算，不能套用模型厂商的直连公开价格。供应商没有承诺本站单次调用的固定延迟。

| 后台 ID | 实际模型与渠道 | 密钥绑定 | JSON 输出方式 |
|---|---|---|---|
| `qwen-flash` | [Qwen3.8 Flash](https://help.aliyun.com/zh/model-studio/qwen3-8-flash)，百炼直连 | `DASHSCOPE_API_KEY` | 严格 JSON Schema；关闭思考 |
| `gpt-luna` | [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)，API易 | `APIYI_API_KEY` | 严格 JSON Schema |
| `deepseek-flash` | DeepSeek Flash，API易 | `APIYI_API_KEY` | JSON Object；该渠道对此模型不支持严格 Schema |
| `gemini-flash-lite` | [Gemini 3.5 Flash-Lite](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite)，BananaRouter | `BANANA_ROUTER_API_KEY` | 严格 JSON Schema；该渠道不接受 JSON Object |
| `runninghub-qwen` | `qwen/qwen3.8-flash-next`，RunningHub | `RUNNINGHUB_API_KEY` | JSON Object；关闭思考 |
| `runninghub-deepseek` | `deepseek/deepseek-v4.1-flash`，RunningHub | `RUNNINGHUB_API_KEY` | JSON Object；关闭思考 |

已用当前密钥直接调用以上文本模型；API易的 `/v1/models` 返回 252 个模型 ID、BananaRouter 的 `/v1/models` 返回 20 个，但**目录可见不等于可用**，表中模型均另做了真实文本调用。两个 LoopRouter Key 只属于图像分组；火山方舟 Key 返回 401（不存在），百度千帆 Key 返回 401（应用无权限）。[长怀平台有文本接口](https://docs.changhuai.ai/otherai/tools/coze/)，但当前 `CHANGHUAI_API_KEY` 请求官方模型目录返回 401，原项目现行配置也无长怀文本渠道；这些 Key 均未接入文本强化。`TENCENT_SECRET_KEY` 是 COS 存储凭证，不是文本模型密钥。

## 同案例实测

下表是 2026-11-10 从当前开发机调用本项目增强逻辑的结果，包含渠道请求、解析与校验，不含浏览器到本站的网络耗时。统一使用系统提示词 V1、下方 5 个案例、每案例 6 轮，按模型串行调用。p50/p95 只对**成功请求**计算，因此必须同时看通过率；这些数值不是供应商 SLA，也未经过成图盲评。

| 后台模型 | 通过 / 请求 | p50 | p95 | 当前处理 |
|---|---:|---:|---:|---|
| `qwen-flash`（严格 Schema） | 30 / 30 | 3949 ms | 4847 ms | 启用，当前默认 |
| `gpt-luna`（API易） | 30 / 30 | 5279 ms | 9495 ms | 启用，质量对照 |
| `gemini-flash-lite`（BananaRouter） | 30 / 30 | 2286 ms | 3187 ms | 启用，速度候选 |
| `runninghub-deepseek` | 30 / 30 | 2842 ms | 4362 ms | 启用，速度候选 |
| `runninghub-qwen` | 28 / 30 | 2893 ms | 3858 ms | 暂停：指令注入案例 2 次未返回有效 JSON |
| `deepseek-flash`（API易） | 11 / 14 | — | — | 暂停：3 次无效 JSON，达到淘汰条件后停止计费测试 |

Qwen 先用 JSON Object 模式做了 30 次，30/30 通过，p50 3555 ms、p95 5768 ms；另一次 5 案例试跑曾漏掉 `user_notice`。根据[阿里百炼结构化输出文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)切换严格 JSON Schema 后再跑上表的独立 30 次。本轮 30/30 通过且 p95 为 4847 ms。RunningHub 的 Qwen 是另一个模型 ID，官方资料[没有明确保证严格 JSON Schema](https://www.runninghub.cn/call-api/llm/models)，不能把百炼的支持情况套用过去。

同一输入「米色亚麻抱枕，放在客厅沙发上，不要文字」的实际强化稿如下。每条还单独返回 `negative_prompt`；例如 Qwen 的排除项含“文字、水印、品牌标识”。

- **百炼 Qwen**：米色亚麻抱枕特写，放置在现代简约客厅的布艺沙发上。面料呈现清晰的天然亚麻纹理与褶皱质感，色调柔和温暖。自然侧光照射，突出材质细节，背景虚化以聚焦主体，画面干净无杂物。
- **API易 GPT**：一只米色亚麻抱枕自然摆放在客厅沙发上，清晰呈现亚麻织纹与柔和的布料褶皱。采用简洁明亮的家居环境和柔和自然光，以略微正面的视角突出抱枕主体，画面整洁，适合家纺电商展示，不出现任何文字。
- **BananaRouter Gemini**：一款米色亚麻抱枕，摆放在现代简约风格的客厅布艺沙发上。抱枕面料呈现出天然亚麻的细腻经纬纹理与柔和质感。场景采用明亮自然的室内光线，背景为干净温馨的家居环境，浅景深突出主体，整体构图平衡，画面无任何文字和水印。
- **RunningHub DeepSeek**：一只米色亚麻抱枕，端正摆放在现代客厅的布艺沙发上，亚麻面料纹理清晰可见，边缘缝线自然；柔和自然光从侧面照入，浅景深突出抱枕主体，正面略侧视角，构图干净简洁，画面中不出现任何文字。

**判定边界**：格式通过与关键词保留只是首层自动校验，不能代替人工检查语义、真实成图质量、用户采纳率和代理渠道实际账单。纯数字案例在服务端始终会被覆盖成已标记的默认稿，本轮通过率衡量整条服务的可用性，不能解释为模型独立识别乱码的准确率。测试顺序按模型分批，网络与渠道负载变化会影响横向延迟对比。

## 分段字段语法 V2 与 V3

2026-11-10 已用 V2 系统提示词及服务端格式整理，对四个启用模型分别测试「明确约束」「画面文字“晚安”」「普通引号商品名」「指令注入」四例，最终各 4/4 通过。主提示词符合 `[标题]`、`字段：值；`、段末 `字段：值。` 的换行格式；需要画出的“晚安”保留引号，普通商品名的装饰性引号被去除。纯数字兜底稿和本地规则预览也通过同一格式校验。可运行 `npm run verify:syntax -- --version=2` 重测旧版。

上述 p50/p95 表格是 **V1** 的独立 30 次批量测试；V2 增加了字段结构和输出长度，耗时不能直接沿用 V1 数字。V2 当前只做了 4 类案例的功能验收，还没有同条件 30 次延迟评测和成图盲评。BananaRouter 的 Gemini 在 V2 请求中曾把 `user_notice` 返回为空数组，服务端现将该非关键说明字段安全归一为空字符串，仍对主提示词、状态和约束做严格校验。

2026-11-10 已将 V3 设为生效版本。四个启用模型针对 7 类案例各测试一次，共 **28/28** 通过；新增案例覆盖同句中的商品名和画面文字引号、未加引号的画面文字，以及否定画面文字。四个模型还分别测试了「不要文字，但写上“晚安”」，均返回单个 `[限制]` 段，负面提示词也只排除指定文字之外的文字；Qwen 对此场景另复测 3 次，分段稿均可用。服务端还会整理模型偶发的独立句号行，避免段标题落入字段值。可运行 `npm run verify:syntax` 重测 V3。

V1 的延迟数据也不能直接代表 V3。V3 尚未做同条件的 30 次延迟评测和成图盲评。

## 内容审核初测

默认使用现有百炼 `qwen-flash` 作为应用级内容分类模型，对输入先审、强化稿再审。2026-11-10 的 8 个单次案例全部符合预期：普通产品、中性历史、公共议题及否定要求放行；现实政治人物的拉票宣传、血腥画面、未成年人性化和注入绕过要求修改。单次审核实测约 0.5～0.9 秒；正常强化需两次审核，实际延迟取决于渠道负载。此为小样本功能检查，不能代表误判率、漏判率或长期 p95；可运行 `npm run verify:moderation` 重测。

现有百炼 API Key 调用的是普通 Qwen 分类提示词，不等同于已开通阿里云[输入输出 AI 安全护栏](https://help.aliyun.com/zh/model-studio/content-security)或[TextModerationPlus](https://help.aliyun.com/zh/document_detail/2671445.html)。上线时须另行验证独立审核服务、实际参考图和最终图片的审核链路。

## 版权角色规则初测

2026-11-12 新增 `IP-001` 与强化审核类别 `copyright_ip`。使用当前配置的 Decisions 审核模型和强化内容审核模型，对钢铁侠、草莓熊、Iron Man、普通原创小熊、原创机械战士、明确排除钢铁侠和草莓熊的原创描述分别真实调用，两套流程均符合预期，共 6/6 组通过。前三例在 Decisions 中命中 `IP-001`，强化审核返回 `copyright_ip`；后三例放行。可运行 `npm run verify:copyright` 重测，产生费用。

本次测试验证文字分类与规则执行；没有实测版权角色参考图的识别准确率，也不能据此推算其他角色、别名、隐喻或长期误漏判率。版权检查拒答、缺题和整体执行失败的禁止生成路径由自动测试验证。平台规则限制可识别第三方角色，不作侵权法律认定。
